# Pants compared with MonoSmith

Pants is an open-source build and developer workflow system for codebases of all
sizes, designed for monorepos. It runs standard tools (compilers, test runners,
linters, formatters, packagers) and speeds them with caching and concurrency.

## What Pants is best at

- **Dependency inference.** Dependencies are modelled through static analysis rather
  than handwritten metadata.
- **Languages.** Python, Go, Java, Scala, Kotlin and Shell, JavaScript (documented as
  beta), plus code generators such as Protobuf, Thrift and Avro, and packaging to Docker images, binaries, AWS
  Lambdas and GCP Cloud Functions.
- **Selecting what changed.** `--changed-since` finds files changed since a commit;
  `--changed-dependents=direct|transitive` adds the targets that depend on them.
- **Remote caching and execution.** Both use the Remote Execution API (REAPI), with
  BuildBarn, Buildfarm and BuildGrid as full servers and `bazel-remote-cache` as a
  caching-only server.
- **A plugin API.** Pants is extensible through a plugin API.
- **Open source.** Apache-2.0.

## Where MonoSmith differs

| | Pants | MonoSmith |
|---|---|---|
| Languages | Python, Go, Java, Scala, Kotlin, Shell; JavaScript in beta | Node, Python, Go, Rust, .NET, Ruby, PHP, C/C++, Dart, JVM, Bicep |
| Remote execution | yes | no |
| Dependency discovery | static analysis of imports | reading imports through each language plugin, plus manifests |
| Release | `pants publish` pushes Python distributions to a PyPI repository (the Python `publish` goal is in an experimental backend), Docker images, Helm charts and Kubernetes manifests; a page shows generating version strings from git state; no changelog or version-bump command found | conventional commits to npm, PyPI, crates.io, NuGet, RubyGems, pub.dev and Maven repositories, Go modules and Packagist by tag |
| CI generation | a CI page with advice, an example GitHub Actions workflow and an `init-pants` action; no generator found | generated for three providers |
| Scaffolding | `pants tailor` generates BUILD files for existing code; no generator for new projects found | `smith add`, recipes |
| Health check | `pants tailor --check` for CI; visibility rules validate dependencies | `smith doctor`, with `--fix` |
| Editors | "We have not yet developed tight IDE integrations, such as a PyCharm plugin or a VSCode extension"; the docs show how to point an IDE at exported virtualenvs | a VS Code extension, a terminal interface and an MCP server |
| Plugin model | a plugin API | out-of-process JSON-RPC plugins in any language |
| Repository status | Apache-2.0, not archived, last push 2026-10-25 (GitHub API, 2026-10-25) | MIT, not archived, first commit 2026-10-15; release 1.62.0 |

Both tools infer the dependency graph from the sources instead of asking you to
write it.

## When to choose Pants instead

- Your repository is Python, Go or JVM heavy, and you want remote execution or a build
  system with dependency inference.
- You need packaging targets such as Lambdas or Cloud Functions that Pants builds.

## When MonoSmith is the better fit

- The repository includes .NET, Rust, Ruby, PHP, Dart or Bicep, none of which the
  documentation lists for Pants, or you need more than Pants's beta JavaScript support.
- You want CI and releases generated by the same tool.

## Moving between Pants and MonoSmith

No automated path in either direction. Moving to smith means adopting the
repository (`smith adopt --dry-run`). This was not tried.
