# Pants compared with MonoSmith

Pants is an open-source build and developer workflow system for codebases of all
sizes, designed for monorepos. It runs standard tools (compilers, test runners,
linters, formatters, packagers) and speeds them with caching and concurrency.

## What Pants is best at

- **Dependency inference.** Dependencies are modelled through static analysis rather
  than handwritten metadata.
- **Languages.** Python, Go, Java, Scala, Kotlin and Shell, plus code generators
  such as Protobuf, Thrift and Avro, and packaging to Docker images, binaries, AWS
  Lambdas and GCP Cloud Functions.
- **Selecting what changed.** `--changed-since` finds files changed since a commit;
  `--changed-dependents=direct|transitive` adds the targets that depend on them.
- **Remote caching and execution.** Both use the Remote Execution API (REAPI), with
  BuildBarn, Buildfarm and BuildGrid as full servers and `bazel-remote-cache` as a
  caching-only server.
- **A plugin API.** Pants is extensible through a plugin API.
- **Open source.** Apache-2.0.

## Where MonoSmith differs

| | Pants | MonoSmith |
|---|---|---|
| Languages | Python, Go, Java, Scala, Kotlin, Shell | Node, Python, Go, Rust, .NET, Ruby, PHP, C/C++, Dart, JVM, Bicep |
| Remote execution | yes | no |
| Dependency discovery | static analysis of imports | reading imports through each language plugin, plus manifests |
| Release | publishing is not described on the page read | conventional commits to eight registries |
| CI generation | not covered by the pages read | generated for three providers |
| Plugin model | a plugin API | out-of-process JSON-RPC plugins in any language |

Both tools infer the dependency graph from the sources instead of asking you to
write it.

## When to choose Pants instead

- Your repository is Python, Go or JVM heavy, and you want remote execution or a build
  system with dependency inference.
- You need packaging targets such as Lambdas or Cloud Functions that Pants builds.

## When MonoSmith is the better fit

- The repository includes Node, .NET, Rust, Ruby, PHP, Dart or Bicep, none of which
  the page read lists for Pants.
- You want CI and releases generated by the same tool.

## Moving between Pants and MonoSmith

No automated path in either direction. Moving to smith means adopting the
repository (`smith adopt --dry-run`). This was not tried.
