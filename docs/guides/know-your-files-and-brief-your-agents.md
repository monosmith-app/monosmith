# Know your files, share the workspace and brief your agents

Three commands answer the questions a new person, a reviewer or a coding agent asks about a
smith workspace. This guide shows them in the order a team meets them.

## Who owns this file

You open a file you did not write. Is it yours to edit?

```sh
smith why packages/web/tsconfig.lib.json
```

`smith why` names the owner, the renderer or command behind the file, the input it follows
from, and how to change it. There are six kinds of answer.

- **Derived by smith.** Change the input (a dependency, a fact, `smith.toml`), then run
  `smith derive`. To keep your own version, run `smith derive --eject <file>`.
- **Ejected.** You own it. Smith does not touch it.
- **Generated by a smith command**, such as a CI pipeline or `AGENTS.md`. `why` names the
  command that rewrites it.
- **`smith.toml`.** Yours. Edit it, or use `smith config`.
- **A file in a project.** Yours. If the project was made from choices (`smith add --with`),
  `why` names the stack and its choices, because a choice may have scaffolded the file once.
- **Unknown.** No project contains it and no record lists it. Smith says so and stops.

`smith why` is not `smith why-miss`. `why-miss <project>:<task>` says why a task ran again
instead of coming from the cache.

## Share the state of the workspace

```sh
smith report -o smith-report.html
```

The page is one file. It has the dependency graph, the doctor results, the derived files that
need action, the stack and choices of each project, and what a merge of the current commit to
the release branch would release. It makes no request and runs no script. Statuses are words,
so a reader who cannot tell colours apart loses nothing. Attach it to a pull request, or
upload it from CI as an artifact (see [`smith report`](../manual/report.md)).

## Brief your agents

```sh
smith agent file
```

This writes `AGENTS.md`, and a `CLAUDE.md` that imports it. The generated part tells an agent:

- where code goes, and the file roles to use in names
- how to add a project with `smith add ... --with ...`
- which commands mean done, ending with `smith ci verify`
- which derived files not to edit by hand
- the stack and the choices of each project

Write your own text anywhere outside the two marker lines. A new run replaces only the lines
between them. If a file has no markers, smith keeps it and adds the region at the end.

Keep the file in step with the workspace. Run `smith agent file` after you change the
architecture, add a project or derive a new file. To make CI catch a stale file, add this step
to your pipeline:

```sh
smith agent file --check
```

It writes nothing and fails when `AGENTS.md` or `CLAUDE.md` is missing or out of date.

`smith agent file` is not `smith agent install`. `install` adds the MonoSmith agent, which
drives smith through its MCP server. `file` writes the rules of your workspace for any coding
agent.
